# 抖音高价值粉丝 · Chrome 扩展（Douyin Fan Ranker）v0.2

一个**在你自己日常使用、已经登录抖音的 Google Chrome 里运行**的扩展。
点一下就能扫描你自己的**全部粉丝**，按**每个粉丝自己的粉丝数从高到低**导出一张
**可以直接用 Excel 打开的 .xlsx 表格**。

> 相比上一版（独立 Playwright 浏览器）：不再启动第二个 Chrome、不用再登录一次、
> 用你当前标签页、事件驱动扫描更快、直接产出 Excel。

---

## 一分钟看懂它怎么工作

- 它**不替你登录**，用的就是你**当前这个已经登录抖音的标签页**。
- 它**不主动请求抖音接口**，只是"在旁边看"浏览器在你滚动时**自己收到的**粉丝列表数据。
- 它用 Chrome 官方的调试协议（CDP）在粉丝列表上**发真实滚轮**让页面继续加载，
  并读取页面**已经收到**的 `follower/list` 响应，解析、去重、保存。
- 扫描完成后**自动下载一个 Excel**，就是"关注我的所有粉丝，按他们各自的粉丝数从高到低排"。

## 一、安装（开发者模式加载）

本扩展未上架 Chrome 应用商店，需要**开发者模式**手动加载已构建的文件夹。

**如果你拿到的是已经构建好的 `dist/` 文件夹**，直接从第 4 步开始。

1. 安装 [Node.js](https://nodejs.org/zh-cn)（LTS 版）。
2. 在项目目录执行：
   ```bash
   npm install
   npm run build
   ```
   构建产物会输出到 **`dist/`** 文件夹（这就是可加载的扩展）。
3. 打开 Chrome，地址栏输入 `chrome://extensions/` 回车。
4. 右上角打开 **「开发者模式」**。
5. 点 **「加载已解压的扩展程序」**，选择项目里的 **`dist/`** 文件夹。
6. 扩展栏会出现「抖音高价值粉丝」图标（可点击拼图图标把它固定到工具栏）。

## 二、使用（核心流程）

1. 在你**平时用的 Chrome**里打开 `https://www.douyin.com/`，确认**已登录**（平时就是登录状态）。
2. 进入**你自己的主页** → 点开「**粉丝**」，让粉丝列表显示出来。
3. 点击工具栏上的扩展图标 →「**开始扫描全部粉丝**」。
4. 页面顶部会出现 Chrome 的提示条：**"‘抖音高价值粉丝’已开始调试此浏览器"**——
   这是正常现象（原因见下方「为什么需要 debugger 权限」）。**扫描期间请不要点它的"取消"**，
   否则会中断（中断也会保存已抓到的数据）。
5. 扩展会**自动向下滚动**粉丝列表并实时显示进度：`已扫描 3820 / 14570 · 26%`。
6. 到达**全部粉丝**或抖音返回**没有更多**时自动结束，**自动下载 Excel**。
7. 中途想停：点「**停止并保存**」，会**立即**导出当前已扫描到的 Excel。

> 扫描时请让该抖音标签页**保持在前台**、粉丝弹窗可见，效果最好。

## 三、输出：Excel 长什么样

自动下载：`抖音粉丝排行榜_YYYY-MM-DD_HH-mm.xlsx`（同时附带一个 `_备份.json` 技术备份）。

**Sheet 1 ·「粉丝排行榜」**（已按粉丝数从高到低排好序）：

| 排名 | 昵称 | 粉丝数 | 关注数 | 作品数 | 抖音号 | sec_uid | 主页 |
| --- | --- | --- | --- | --- | --- | --- | --- |

- 「粉丝数/关注数/作品数」是**真正的数字单元格**（带千分位格式），不是"12.3万"这种字符串，可直接排序求和。
- 「主页」是**超链接**，点开就是该粉丝主页 `https://www.douyin.com/user/{sec_uid}`。
- **冻结首行**、**自动筛选**、合理列宽、中文正常显示。

**Sheet 2 ·「数据概览」**：总粉丝数、本次成功扫描数、各量级人数分布
（100万+ / 10万~100万 / 1万~10万 / 1000~1万 / 100~1000 / 100以下）、以及 **Top 20** 高粉丝账号。

## 四、为什么需要 debugger 权限（重要说明）

本扩展申请了 `debugger` 权限。原因：

- 抖音的粉丝数据在**已经收到的网络响应**里。要读取"响应正文（response body）"，
  标准且**不伪造请求**的方式，是通过 Chrome 官方的 **DevTools 协议（CDP）** 的
  `Network.getResponseBody`——而使用 CDP 必须申请 `debugger` 权限。
- 同样地，为了在粉丝列表上产生**真实滚轮**让页面自己加载下一页，用的是 CDP 的
  `Input.dispatchMouseEvent`，也需要该权限。

我们**只**用它做两件事：**读取已到达的 `follower/list` 响应正文** + **发送滚轮**。
它**不会**读取或导出你的 Cookie / Token，**不会**构造任何抖音接口请求。
附着调试器时 Chrome 会显示提示条，属于该权限的正常安全提示。

**申请的权限（已尽量最小化）：**

| 权限 | 用途 |
| --- | --- |
| `debugger` | 用 CDP 读取已到达响应正文、发送真实滚轮（见上） |
| `activeTab` | 对你当前打开的抖音标签页生效 |
| `downloads` | 扫描结束后把 Excel / JSON 下载到你本机 |
| `host_permissions: *://*.douyin.com/*` | 只在抖音域名注入内容脚本、只调试抖音标签页 |

> 说明：数据用浏览器内置的 **IndexedDB** 本地保存，**不需要** `storage` 权限，所以没有申请它。

## 五、安全边界（严格遵守）

- ✅ 只**被动读取**浏览器在你正常浏览时**已经收到**的响应；
- ❌ 不主动构造 / 重放 `follower/list` 请求；
- ❌ 不生成 / 不伪造 `a_bogus`、`msToken`、`verifyFp`、签名、Cookie；
- ❌ 不读取 / 不导出 Cookie、Token；
- ❌ 不并发轰炸接口、不批量打开每个粉丝主页；
- ❌ 不绕过验证码 / 安全验证——**一旦检测到就立即停止**并保存已抓数据；
- ❌ 不把任何数据上传到服务器——**所有数据只保存在你本机浏览器里**。

> ⚠️ 自动化浏览仍可能受平台规则、风控与页面结构变动影响，**不保证永久可用或零风险**。
> 检测到"验证码 / 安全验证 / 操作频繁 / 访问过于频繁"等提示时，扩展会主动停止。

## 六、扫描是怎么做到又快又稳的

- **事件驱动**，不再是"滚一下→死等 2 秒"：发出滚轮后，**新的 `follower/list` 响应一到就立刻**
  解析下一批、继续滚动；只有真的没数据才短暂等待。这样把速度交给"网页自身加载多快"，
  而不是人为把几百批分页拖成一小时。同时保留**最小节流**，绝不疯狂滚动或并发。
- **卡住自动恢复**：连续几次没有新数据时，自动重新定位粉丝面板、重取坐标、重发滚轮、
  检查滚动位置，多试几次；只有**多次恢复仍无新数据**才判定结束
  （"扫描停止：长时间未获取到新数据"），并保存结果。
- **完成条件**：已扫描数 ≥ `real_fans_count`，或抖音返回 `has_more = false`。
- **断点续扫**：扫描过程持续写入 IndexedDB；即使插件/Service Worker 意外重启也尽量保住已抓数据。
  下次点"开始扫描"会自动读回已有数据并以 `sec_uid` 去重——从粉丝列表顶部重新滚也没关系，
  已有的人自动跳过，继续往下补，直到扫完。

## 七、项目结构（开发者）

```text
douyin-fan-ranker/
├─ manifest.json            # MV3 清单（构建时拷入 dist/）
├─ src/
│  ├─ background/index.ts   # Service Worker：CDP 抓包 + 滚动编排 + 生成/下载 Excel
│  ├─ content/index.ts      # 内容脚本：识别粉丝面板、返回坐标/scrollTop、检测验证
│  ├─ popup/                # 弹窗 UI（popup.html / popup.ts / popup.css）
│  └─ lib/                  # 纯逻辑（可单测，被上面复用）
│     ├─ parser.ts          # 容错解析 follower/list 响应（从旧版迁移）
│     ├─ dedup.ts           # sec_uid 去重 + followerCount 降序（从旧版迁移）
│     ├─ panel.ts           # 粉丝面板识别评分（纯 DOM，jsdom 可测）
│     ├─ overview.ts        # 概览统计（分桶 + Top20）
│     ├─ xlsx.ts            # ExcelJS 生成工作簿
│     ├─ db.ts              # IndexedDB 持久化
│     ├─ utils.ts / types.ts / messages.ts / scan-config.ts
├─ scripts/build.mjs        # esbuild 打包 + 拷贝静态资源 → dist/
├─ scripts/make-icons.mjs   # 生成图标
├─ test/                    # vitest 单元测试
├─ fixtures/                # 纯虚构示例响应（无任何真实账号/Token）
└─ dist/                    # 构建产物：可加载的未打包扩展（.gitignore 忽略）
```

### 常用命令

```bash
npm install       # 安装依赖
npm run build     # 构建扩展到 dist/（再到 chrome://extensions 加载 dist/）
npm run typecheck # TypeScript 类型检查
npm test          # 运行全部单元测试
npm run lint      # 代码风格检查
```

### 可调参数（`src/lib/scan-config.ts`）

滚轮 `deltaY`、最小节流、等待新响应超时、恢复次数/等待、量级分桶等均在此集中调整。
