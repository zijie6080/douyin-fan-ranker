# 抖音粉丝分析工具（Douyin Fan Ranker）v0.1

一个**在你自己 Windows 电脑上本地运行**的小工具。它会打开一个真实的 Chrome 浏览器，
让你**自己登录**抖音、**自己打开**粉丝列表，然后自动帮你**慢慢向下滚动**，
把浏览器页面自己加载出来的粉丝数据收集下来，**按每个粉丝自己的粉丝数从多到少排序**，
最后生成一个可以用 Excel 打开的表格（CSV）和一个 JSON 文件。

> ⚠️ 这是一个**本地运行的原型工具**。当前为**全量扫描模式**：没有人为数量上限，
> 会自动扫描到账号当前的完整粉丝列表结束（以接口返回的 `real_fans_count` 为目标总数）。

---

## 它是怎么工作的（用大白话讲）

- 程序**不会**替你登录，也**不会**去"偷偷请求"抖音的接口。
- 程序只是**打开一个浏览器**给你用。你自己登录、自己点开粉丝列表。
- 抖音网页在你向下滚动时，**它自己**会去加载下一批粉丝（这是网页本来就有的行为）。
- 程序做的，只是**在旁边"看"浏览器已经收到的数据**，把粉丝信息记录下来。
- 就像你自己一边翻粉丝列表、一边用笔记本抄下来，只不过由程序自动完成。

换句话说：**程序只监听、只整理，不主动向抖音发任何请求。**

## 一、安装（第一次使用需要）

### 需要什么

1. 一台 **Windows 电脑**
2. 已经安装 **Google Chrome 浏览器**（大多数人都有）
3. 安装 **Node.js**（这是运行本程序的基础环境）
   - 下载地址：<https://nodejs.org/zh-cn>
   - 选择"**LTS（长期支持版）**"下载安装，一路点"下一步"即可
   - 建议版本 18 或更高

### 怎么启动

把本项目文件夹放到电脑上任意位置，然后：

- **双击 `start.bat`** 即可（推荐，最简单）

第一次启动时，它会自动：

1. 检查你有没有装 Node.js（没有会提示你去装）；
2. 自动下载程序需要的组件（这一步只有第一次需要，可能要几分钟，请耐心等）；
3. 打开浏览器，开始使用。

> 如果 `start.bat` 打不开，也可以右键 `start.ps1` → "使用 PowerShell 运行"。

## 二、第一次运行 —— 如何登录

1. 双击 `start.bat` 后，程序会**自动弹出一个 Chrome 浏览器**，并打开抖音首页。
2. 在这个浏览器里，**像平常一样登录你自己的抖音账号**（扫码或短信都行）。
3. 登录信息会保存在项目里的 `.browser-profile/` 文件夹，**以后再运行会自动复用，正常情况下不用再登录**。

> 这个浏览器是程序专用的，和你平时用的 Chrome 是分开的，不会读取你原来的浏览器数据。

### 关于“保持登录”（重要）

- **只需第一次登录一次。** 登录状态保存在项目目录下的 `.browser-profile/` 文件夹里，
  之后每次运行都会**复用同一个文件夹**，所以正常情况下**不会**每次都要重新登录。
- 程序启动时终端会打印它正在使用的 profile 目录，例如：
  `登录 profile 目录：C:\...\douyin-fan-ranker\.browser-profile`，
  并提示“检测到已保存的登录 profile”。**每次看到的目录应该是同一个。**
- 想真正保持登录，请注意：
  - **保留 `.browser-profile/` 文件夹**，不要删除它，也不要把新下载的项目覆盖到它上面。
  - 建议用完通过程序正常结束（扫描完成会自动退出）或按一次 `Ctrl+C`，让登录状态写入磁盘。
  - **强烈建议安装 Google Chrome**：程序优先用系统 Chrome。若没装 Chrome 会回退到内置
    Chromium（用另一个独立目录 `.browser-profile-chromium/`），装上 Chrome 后登录会最稳定。
- 如果确实需要**切换账号 / 清除登录**：双击 **`reset-login.bat`**（或命令行 `npm run reset-login`），
  它会删除已保存的登录 profile，下次运行重新登录即可。**这是唯一会删除登录的操作**，程序平时不会删。

如果你发现每次都要重新登录，请对照排查：

1. 你是不是每次都**重新解压了一份新的项目**到新文件夹？换新文件夹 = 没有旧的 `.browser-profile/`。
   请固定用同一个项目文件夹。
2. 启动日志里的“登录 profile 目录”每次是否**一致**？不一致说明启动目录变了。
3. 有没有装 Google Chrome？装了会走 Chrome 稳定复用；没装会走 Chromium（另一个目录）。

## 三、如何开始扫描 —— 打开你的粉丝列表

1. 登录后，在这个浏览器里**进入你自己的主页**。
2. 点击页面上的「**粉丝**」，让粉丝列表（通常是一个弹窗或侧边栏）**显示出来**。
3. **确认能看到粉丝头像和名字**后，回到黑色的终端窗口，**按一下 Enter 键**。
4. 程序就会开始**自动慢慢向下滚动**粉丝列表并收集数据。

终端里会实时显示进度，例如：

```
已收集 40 / 14570 | 捕获接口 2 次 | 当前最高：某某某 - 382,000 粉丝
```

- `40` 是已经收集到的不同粉丝数；
- `14570` 是抖音显示的你的真实粉丝总数（从接口的 `real_fans_count` 读到）；
- **全量扫描模式：没有人为数量上限**，会一直滚动直到收集完整个粉丝列表。

### 什么时候会停止？

**正常完成**（任一）：

1. 已收集数量达到 `real_fans_count`（例如 `已收集 14570 / 14570`）；
2. 抖音返回"没有更多了"（`has_more = false`）。

完成时显示：`✅ 扫描完成：已保存 14570 / 14570`。

**安全 / 异常暂停**（任一，程序会**先保存再退出**，不会清空数据）：

3. 页面出现**验证码 / 滑块 / 安全验证 / 操作过于频繁 / 访问过于频繁**等提示
   —— 此时程序**只会停止，绝不会尝试绕过**；
4. `follower/list` 接口**连续失败**多次；
5. 较长时间（约 20~30 秒）没有再收到新的粉丝列表响应（判定到底或加载停滞）；
6. 多次滚动后位置不再变化。

暂停时显示：`🛑 扫描暂停：已保存 6832 / 14570`。

**你主动停止**：扫描过程中**随时按 `Q` 或 `Ctrl + C`**，程序都会**先保存再退出**。

> 断点续扫：无论是异常暂停还是你主动停止，数据都已存进 `output/fans.json`。
> **下次运行会自动读取已有数据并以 `sec_uid` 去重**——程序会重新从粉丝列表顶部开始滚动，
> 已保存的用户直接跳过，继续往下滚到还没保存的新用户，最终把整份粉丝列表扫完。

## 四、输出在哪里 —— CSV 怎么打开

扫描结束后，结果保存在项目的 **`output/` 文件夹**里：

- `output/fans.csv` —— 表格文件，**可以直接用 Excel 打开**（已处理好中文编码，不会乱码）。
- `output/fans.json` —— 原始数据（给需要进一步处理的人用）。

CSV 表格包含这些列，并且**已经按粉丝数从多到少排好序**：

| 列名 | 含义 |
| --- | --- |
| `rank` | 排名（粉丝数越多排越前） |
| `nickname` | 昵称 |
| `follower_count` | 该粉丝自己的粉丝数 |
| `following_count` | 该粉丝关注了多少人 |
| `aweme_count` | 作品数 |
| `sec_uid` | 抖音用户唯一标识 |
| `unique_id` | 抖音号 |
| `profile_url` | 该粉丝主页链接 |

> 程序在扫描过程中会**边收集边保存**，即使中途关闭，已收集的数据也不会全部丢失。
> 下次重新运行时，会自动读取上次的结果作为缓存并去重（同一个人不会重复）。

## 五、安全说明（请务必阅读）

本工具在设计上严格遵守以下边界：

- ✅ **只监听**浏览器在你正常浏览时**已经收到**的网络响应；
- ❌ **不会**主动构造、发送或重放任何抖音接口请求；
- ❌ **不会**硬编码或伪造 Cookie、msToken、a_bogus、verifyFp 等任何签名/会话参数；
- ❌ **不会**尝试任何签名算法，**不会**尝试绕过验证码或安全验证；
- ❌ **不会**并发请求，**不会**批量打开每个粉丝的主页；
- ❌ **不会**把你的任何数据上传到任何服务器 —— **所有数据只保存在你自己的电脑上**；
- ❌ 终端**不会**打印完整请求地址、query 参数、Cookie、Token 或请求头等敏感信息。

**重要提示：**
自动化浏览行为**仍可能受到平台规则、风控策略和页面结构变动的影响**。
本工具**不保证永久可用、也不保证零风险**。请你在了解并接受这一点的前提下、
在自己的账号上、按平台规则合理使用。检测到任何验证或异常时，程序会主动停止。

### 可调参数（`src/config.ts`）

- **全量扫描：已无数量上限**，扫描目标总数取自 Response 的 `real_fans_count`。
- `FOLLOWER_LIST_PATH`：用于匹配响应的路径子串 `/aweme/v1/web/user/follower/list/`。
- `FOLLOWER_LIST_FAIL_LIMIT`：接口连续失败多少次判定异常并暂停（默认 5）。
- 滚轮 `deltaY`、每轮尝试次数、等待时间、各类停止阈值等，均在此集中调整。

### 滚动是怎么实现的（v0.2 改动）

抖音粉丝列表很可能是**虚拟列表 / React 滚动组件**——直接用 JS 修改 `element.scrollTop`
**不一定会触发它真正的"加载下一页"逻辑**（这正是早期版本"只有手动滚鼠标才继续加载"的原因）。

因此现在的主滚动方式改为 **Playwright 真实鼠标滚轮输入**：

1. `findFollowerPanel()`：综合评分识别当前可见的粉丝面板——可滚动、在视口内、
   高度足够、含大量头像/用户行、附近有「回关/移除/已关注」文案、处于 dialog/overlay 浮层内等，
   **不依赖任何固定 class 或单一关键词**；并取其 bounding box。
2. 把鼠标移动到面板中央偏下（首次先点击一下使其进入交互状态）。
3. `page.mouse.wheel(0, deltaY)` 发出**真实滚轮事件**（每次 600~1000 像素）。
4. **以"是否产生新的 `follower/list` Response"作为滚动成功标准**：每轮记录接口捕获次数，
   滚轮后短等待再比较；一轮内允许连续尝试多次（可能只是还没滚到底部附近）。
5. **每轮重新定位面板**，避免虚拟列表重渲染导致的 stale 元素。
6. DOM `scrollTop` 仅作为真实滚轮完全无效时的**兜底手段**保留。

> 调试：设置环境变量 `DEBUG_SCROLL=true` 运行，会给识别到的粉丝面板**画红框**并打印详细日志
> （鼠标落点、滚轮 deltaY、每次尝试是否捕获到新请求等），方便真机确认程序框对了区域。
> 日志**不会**打印 Cookie / Token / 完整 URL / query 等敏感信息。

### 关于"字段结构可能不同"

本工具对响应字段做了**容错解析**：优先找 `user_list` / `users` / `followers` 等常见键，
找不到就**递归搜索**出"看起来像粉丝用户数组"的结构（元素含 `nickname` 与 `follower_count`）。
即便如此，抖音真实响应结构仍可能与示例不同。如果你在真机联调时发现解析结果不对，
请参考文末「如何反馈」提供信息，以便修正。

## 七、重要：真实抖音联调必须在你本地完成

本项目是在**云端开发环境**里编写和测试的，**云端无法登录你的真实抖音账号**，
因此**没有、也不能进行真实抖音端到端测试**。

已经在云端验证的部分：
- TypeScript 编译通过、全部单元测试通过、代码风格检查通过；
- 用**真实 Chromium 浏览器**验证了：面板识别正确，且 `page.mouse.wheel()` 的**真实滚轮输入**
  能触发页面"加载更多"（在一个"只响应 wheel 事件、不响应 scrollTop"的模拟弹窗上，列表由 20 行自动增长到 60 行，全程未手动碰鼠标）；
- 用**虚构的示例响应**验证了解析、去重、排序、CSV/JSON 输出全部正确。

**只有你在自己的 Windows 电脑上、登录真实抖音后，才能完成最终的真机联调。**
这一步必须由你本人完成。

## 八、如何反馈（当真实响应和示例不一致时）

如果真机运行时数据不对，请把**以下信息**发给维护者（**注意脱敏**）：

1. 你在浏览器 DevTools → Network 里，看到的 `follower/list` 响应的**顶层字段名**（例如 `user_list` 还是别的）；
2. **单个粉丝对象**的字段结构（把 `nickname`、`follower_count`、`sec_uid` 等键名列出来即可）；
3. 头像字段的结构（例如是 `avatar_thumb.url_list` 还是别的）；
4. 终端里程序打印的**停止原因**和**已收集数量**。

> ⚠️ 反馈时请**务必删除**：完整 URL、query 参数、Cookie、msToken、任何 Token、
> 以及任何真实账号的敏感信息。只需要提供**字段名和结构**，不需要真实数据值。
